# HolliHop Telegram Bot

Telegram-бот на Node.js + MySQL для **массовых рассылок родителям и ученикам по филиалам**.
Данные (филиалы, ученики, родители/контактные лица) автоматически синхронизируются из **HolliHop API 2.0**.

## Как это работает

1. **Синхронизация** (`src/hollihop/sync.js`): `GetOffices` → филиалы, `GetStudents` → ученики, контактные лица (родители) и их телефоны.
   Инкрементально каждые 10 минут (`lastUpdatedFrom`), полностью — раз в ночь (удаляет учеников, которых больше нет в HolliHop).
2. **Регистрация получателей**: Telegram не позволяет писать человеку первым — он сам должен запустить бота.
   Пользователь жмёт `/start`, отправляет **ID ученика из HolliHop** и выбирает, кем он приходится (родитель / ученик).
   Один родитель может добавить несколько детей. Имя ученика показывается сокращённо («Иван П.»), перебор ID ограничен (5 неудачных попыток в час).
   Если ученика ещё нет в БД (создан в HolliHop после последней синхронизации), бот сам запрашивает его в HolliHop (`GetStudents` по `id`/`clientId`) и сохраняет в БД.
   Защита: не более 20 таких запросов в минуту на весь бот и кэш «не найдено» на 10 минут (HolliHop блокирует перебор данных через API).
   Какой именно ID используется (`Id` или `ClientId`), задаётся в `.env`: `REG_ID_FIELD=hh_id|client_id`.
3. **Рассылка** (администратор): `/broadcast` → выбор филиалов → аудитория (родители / ученики / все) → отправляете сообщение → подтверждение.
   Рассылка идёт в фоне (~20 сообщ./сек), переживает рестарт, учитывает 429 от Telegram, помечает заблокировавших бота.
   Сообщение копируется целиком (`copyMessage`): текст, фото, видео, документ, форматирование, подпись.

## Быстрый старт

```bash
cp .env.example .env      # заполните BOT_TOKEN, ADMIN_IDS, DB_*, HH_SUBDOMAIN, HH_AUTH_KEY
npm install
npm run migrate           # создать таблицы (также выполняется при старте)
npm start
```

Docker: `docker compose up -d --build` (поднимет MySQL 8 и бота).
PM2: `pm2 start ecosystem.config.cjs`.

### Что нужно из HolliHop
- **HH_SUBDOMAIN** — поддомен вашей школы (`https://<поддомен>.t8s.ru`). `hollipedia.t8s.ru` — это только документация.
- **HH_AUTH_KEY** — ключ из *Настройки → Интеграция → API*. Храните только в `.env`, на сервере. Лимит API: 600 запросов / 30 сек (клиент сам ждёт и повторяет).

## Языки (казахский / русский)
По умолчанию бот говорит **по-казахски**. На первом `/start` пользователь выбирает язык (🇰🇿 Қазақша / 🇷🇺 Русский), позже его можно сменить командой `/lang`.
Язык хранится в `tg_users.lang`; до выбора все тексты на казахском. Меню команд в Telegram (названия команд — только латиницей) тоже переключается на выбранный язык.
Обращение к родителю в рассылке («Құрметті … оқушысының ата-анасы!» / «Уважаемый родитель ученика …!») пишется на языке получателя; основной текст рассылки уходит как написан администратором.
Все строки лежат в `src/i18n.js` (там же добавляется новый язык). Админские команды и интерфейс админки — на русском.

## Языки бота (қазақша / русский)
По умолчанию **весь бот на казахском**. При первом `/start` пользователь выбирает язык (кнопки 🇰🇿 / 🇷🇺), выбор хранится в `tg_users.lang` и меняется командой `/lang`.
Язык влияет на все тексты бота, меню команд (оно ставится отдельно для чата) и обращение «Уважаемый родитель ученика …» в рассылках (`Құрметті … оқушысының ата-анасы!`).
Пока язык не выбран, всё приходит на казахском. Тексты лежат в `src/i18n.js`; чтобы добавить язык, добавьте код в `LANGS`, словарь в `DICT` и описания команд в `COMMANDS`.
Админские команды и веб-админка остаются на русском. Текст самой рассылки пишете вы (можно сразу на двух языках).

## Команды

Пользователь: `/start`, `/me`, `/unlink`, `/stop`, `/resume`, `/help`.
Администратор (ID в `ADMIN_IDS`): `/broadcast`, `/broadcasts`, `/stopbroadcast <id>`, `/stats`, `/sync [full]`, `/adminhelp`.

`/stats` показывает по каждому филиалу: сколько учеников в базе и скольким из них реально можно написать (кто подключился к боту).

## Веб-админка

Задайте в `.env` `ADMIN_WEB_PASSWORD` — и по адресу `http://сервер:3000` (порт `ADMIN_WEB_PORT`) откроется админка:
список учеников с фильтрами **по статусам и филиалам (можно выбрать несколько сразу), по ID ученика / ФИО** и по подключению к боту, пагинация (50 на страницу),
карточка ученика (контакты, родители, подключённые Telegram-аккаунты), экспорт отфильтрованного списка в Excel и счётчики сверху.
Вход по паролю, сессия 12 часов, ограничение попыток входа. **Выставляйте админку наружу только через HTTPS** (nginx/Caddy) и ставьте `ADMIN_WEB_SECURE_COOKIE=1`.

### Страница выгрузок для менторов (`/mentor`)
Отдельный вход `/mentor/login` (логин + пароль), без доступа к админке и рассылкам. Две учётки:

| Учётка | `.env` | Видит филиалы |
|---|---|---|
| Ментор Алматы | `MENTOR_ALMATY_LOGIN` (по умолчанию `almaty`), `MENTOR_ALMATY_PASSWORD` | только `MENTOR_ALMATY_BRANCHES` (по умолчанию `Сейфуллина`) |
| Ментор Астана | `MENTOR_ASTANA_LOGIN` (по умолчанию `astana`), `MENTOR_ASTANA_PASSWORD` | все остальные филиалы |

Учётка без пароля отключена. Переход между админкой и выгрузками в любую сторону требует пароль: в браузере активна только одна сессия — вход в админку завершает сессию ментора и наоборот. Все выгрузки — в Excel (.xlsx).
«Активные ученики» — статусы `MENTOR_ACTIVE_STATUSES` (по умолчанию `Занимается,Регистрация,Заморозка`).

- **Не зарегистрированы в боте** (из БД бота): фильтр по статусу и филиалу, режим «никто / нет родителя / нет ученика»;
  ID HolliHop, ФИО, статус, филиал, телефон ученика, родители с телефонами.
- **Не посещают** (HolliHop): активные ученики, у которых за последние 7 дней нет ни одного результата теста категории
  `MENTOR_ATTENDANCE_TEST_CATEGORY` (по умолчанию `old daily`) — ни группового (`GetEdUnitTestResults`), ни персонального (`GetPersonalTestResults`).
  В файле — дата последнего такого результата за 30 дней.
- **Адаптация** (HolliHop): активные ученики, созданные за последние 7 дней.
- **Ежедневная** (HolliHop + «Мои звонки»): вводится день обзвона (значение поля «День обзвона постоянное», 0–10) и дата звонков (по умолчанию сегодня).
  Лист «Сводка» — всего и по каждому ментору: запланировано (ученики с этим днём), «Статус звонка» = Дозвон, фактически был разговор
  больше 90 секунд за эту дату (номер ученика или родителей). Лист «Ученики» — список с отметкой «Фактический звонок».
- **14+** (HolliHop + «Мои звонки»): активные ученики, с которыми за 14 дней не было разговора от 90 секунд ни на номер ученика,
  ни на номера родителей (звонков нет или все короче 90 сек, считается поле `duration` — время разговора).
  Колонки: ID, ФИО, статус, моб. телефон, ментор (ответственный в HolliHop), «День обзвона постоянное», «Статус звонка»,
  плюс филиал, число звонков и самый длинный разговор. Доступ к API — `MOIZVONKI_URL`, `MOIZVONKI_USER`, `MOIZVONKI_API_KEY`
  (Мои звонки → Настройки → Интеграция → API); все звонки компании за 14 дней выгружаются разом (`calls.list`, `supervised: 1`) и сопоставляются по последним 10 цифрам номера.
- **Проверка данных** (HolliHop): нет фото, не заполнены пользовательские поля `MENTOR_SCHEDULE_FIELD` (`РАСПИСАНИЕ`) / `MENTOR_TIME_FIELD` (`ВРЕМЯ ЗАНЯТИЙ`),
  ученик не в группе, или **расписание некорректно** — дни из поля не совпадают с днями текущих групп ученика (`GetEdUnits` → действующие `ScheduleItems`)
  либо начало занятий отличается больше чем на 10 минут. Отдельная колонка на каждую проблему и текст расхождения.

Данные из HolliHop кэшируются на 10 минут (галочка «Обновить» берёт свежие).

### Отдельное сообщение на каждого ученика
Если у родителя несколько детей, он получает **отдельное сообщение на каждого ученика** с обращением в начале:
«**Уважаемый родитель ученика Иванов Иван!**» и ниже — текст рассылки. Ученикам (кто подключился как «я ученик») обращение не добавляется.
В вебе это можно отключить галочкой (тогда одно сообщение на человека). В боте (`/broadcast`) обращение уходит отдельным сообщением перед скопированным.
Количество людей и сообщений показывается перед отправкой.

### Рассылка из веб-админки
На главной выберите фильтры (статус / филиал / ID или ФИО) → **«📣 Рассылка по фильтру»** → выберите аудиторию (родители / ученики / все), введите текст,
поставьте галочку подтверждения → **«Отправить»**. Ход отправки — на странице **«Рассылки»** (обновляется сама, есть кнопка «Остановить»).
Получают только те, кто подключился к боту и не отписался. Из веба уходит текст (опционально с HTML: `<b>`, `<i>`, `<a href>`);
сообщения с фото/видео/файлами рассылайте из бота командой `/broadcast`.

## Нюансы и настройки

- **Фильтр по статусу ученика**: `RECIPIENT_STATUSES=Занимается,Регистрация,Заморозка` — в БД попадают (и рассылка идёт) только ученики с этими статусами HolliHop (названия как в настройках CRM, регистр не важен). Ученик, перешедший в другой статус, удаляется из БД при ближайшей синхронизации вместе с привязками к Telegram. После изменения списка выполните `/sync full`. Пусто — без фильтра.
- **Инкрементальная синхронизация** в HolliHop учитывает только смену статуса, контактов и ответственных — смену филиала подхватит ночная полная синхронизация (или `/sync full`).
- **Альбомы** (несколько фото одним сообщением) рассылаются по одному сообщению: для рассылки присылайте одно фото/видео с подписью.
- Рассылка фиксирует список получателей в момент запуска; новые подписчики в уже идущую рассылку не попадают.
- Персональные данные детей и родителей: ограничьте доступ к БД и серверу и убедитесь, что хранение соответствует законодательству о персональных данных вашей страны.

- **Безопасность регистрации**: ID ученика — единственная «проверка», а ID обычно идут подряд, поэтому посторонний теоретически может подобрать чужой ID и получать рассылки. Если это критично, добавьте второй фактор (например, последние 4 цифры телефона из HolliHop).
